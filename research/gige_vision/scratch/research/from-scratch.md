## 1. The premise about "GigE Vision 3" (short; other topics cover it in depth)

* GigE Vision 3.0 came out on **2026-05-12**. It adds **RoCEv2 / RDMA streaming (GVRSP)** and a larger control channel. The press release says nothing about PTP. Source: the [Vision Systems Design press release](https://www.vision-systems.com/directory/software/machine-vision-imaging-software/press-release/55377111/association-for-advancing-automation-a3-a3-officially-releases-gige-vision-30-opening-new-possibilities-in-machine-vision), which I read. The automate.org FAQ returned HTTP 403.
* IEEE 1588 is a **GigE Vision 2.0** feature, judging by the code. Wireshark tags the capability bit `hf_gvcp_capability_1588_v2_0` (mask `0x00080000`, [W/packet-gvcp.c#L3474-3477](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L3474-3477)). It also tags the enable bit `hf_gvcp_configuration_1588_enable_v2_0` (mask `0x00080000` in GVCP Configuration `0x0954`, [#L3604-3607](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L3604-3607)) and `hf_gvcp_ieee1588_clock_status_v2_0` (`0x096C`, mask `0xF`, [#L3692-3695](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L3692-3695)). The 2.1 profile registers sit at `0x0974–0x097C` ([#L132-136](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L132-136)). Single-cable PTP sync therefore works with **any GEV ≥2.0 camera that sets capability bit 0x00080000**. It does not need GEV 3.0.
* For a from-scratch client, GEV 3.0's new transport (RDMA) means libibverbs plus RoCEv2 NICs at 25 GbE and above. That is outside what pure Python can do. Grepping Aravis `src/`, both Wireshark dissectors, and the telegenic and viva-genicam READMEs finds no GVRSP/RDMA support anywhere (the `grep -i 'gvrsp|rdma|roce'` hits were all false positives such as "processing").

## 2. Minimum protocol surface, with where each piece is implemented

### 2.1 GVCP (UDP 3956, one command in flight, 8-byte header)
* Port and header: `ARV_GVCP_PORT 3956` ([A/src/arvgvcpprivate.h#L36](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L36)). The command header is `{u8 0x42, u8 flags, u16 command, u16 length, u16 req_id}` ([#L284-303](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L284-L303)). `req_id` 0 is invalid, so the counter wraps 0xffff→1 ([#L530-537](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L530-L537)). Status codes are listed at [#L157-209](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L157-L209).
* Command codes come from Wireshark ([W/packet-gvcp.c#L177-197](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L177-197)): DISCOVERY 0x0002/3, **FORCEIP 0x0004/5**, PACKETRESEND 0x0040, READREG 0x0080/1, WRITEREG 0x0082/3, READMEM 0x0084/5, WRITEMEM 0x0086/7, PENDING_ACK 0x0089, EVENT 0x00C0, **ACTION 0x0100/1**. Aravis' enum has no FORCEIP or ACTION entries and calls 0x0004 `BYE_CMD` ([A/src/arvgvcpprivate.h#L267-281](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L267-L281)). Its ForceIP support only appears as an IP-configuration *mode* enum.
* **DISCOVERY**: the command is header-only, with flags `ACK_REQUIRED|ALLOW_BROADCAST_ACK(0x10)` and id 0xffff ([A/src/arvgvcp.c#L341-358](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcp.c#L341-L358)). It is sent per interface to the subnet broadcast with `SO_BROADCAST` ([A/src/arvgvinterface.c#L52-60](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvinterface.c#L52-L60), [#L80-140](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvinterface.c#L80-L140)). The ACK payload is 0xF8 bytes, the first 0xF8 bytes of the bootstrap map ([A/src/arvgvcpprivate.h#L38-80](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L38-L80)). Field offsets: version@0, mode@4, MAC@10, IP config@16/20, IP@36, mask@52, gateway@68, manufacturer@72, model@104, device version@136, mfr info@168, serial@216, user name@232 ([W/packet-gvcp.c#L2121-2195](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L2121-2195)). pyGigEVision also handles a vendor variant that shifts the strings by 24 bytes ([gvcp.py#L124-183](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/gvcp.py#L124-L183)).
* **FORCEIP**: payload is MAC@+2, IP@+20, mask@+36, gateway@+52 ([W/packet-gvcp.c#L1531-1548](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L1531-1548)). pyGigEVision implements it ([gvcp.py#L426](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/gvcp.py#L426)) and has tests ([tests/test_forceip.py](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/tests/test_forceip.py)). Telegenic defines it at [src/gige/proto/gvcp.rs#L26-46](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/src/gige/proto/gvcp.rs#L26-L46).
* **READREG/WRITEREG/READMEM/WRITEMEM**: the READMEM payload is `{u32 addr, u32 size rounded to 4}` ([A/src/arvgvcp.c#L55-79](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcp.c#L55-L79)). Aravis caps the data at `ARV_GVCP_DATA_SIZE_MAX 512` ([arvgvcpprivate.h#L139](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L139)). Transactions with retries live in `_send_cmd_and_receive_ack` ([A/src/arvgvdevice.c#L138](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvdevice.c#L138)). Telegenic notes that multi-register READREG/WRITEREG only works when the device advertises the CONCATENATION capability ([CHANGELOG 2.0.3](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/CHANGELOG.md)).
* **CCP 0x0A00** (bit1 = control, bit0 = exclusive) ([A/src/arvgvcpprivate.h#L122-124](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L122-L124); take control at [A/src/arvgvdevice.c#L523-550](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvdevice.c#L523-L550)). **Heartbeat timeout 0x0938** ([arvgvcpprivate.h#L115](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L115)). Aravis's heartbeat thread re-reads CCP ([arvgvdevice.c#L448-508](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvdevice.c#L448-L508)) every 1 s ([arvgvdeviceprivate.h#L37-45](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvdeviceprivate.h#L37-L45)). pyGigEVision does the same every 2 s ([gvcp.py#L929-951](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/gvcp.py#L929-L951)). The Aravis fake camera counts any READREG of CCP as a heartbeat ([arvgvfakecamera.c#L189-200](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvfakecamera.c#L189-L200)).
* **GenICam XML**: First URL at `0x0200`, second at `0x0400`, 512 bytes each ([arvgvcpprivate.h#L82-84](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L82-L84)). Aravis parses `Local:` / `file:` URLs, reads the blob with READMEM and unzips a `.zip` ([A/src/arvgvdevice.c#L1266-1397](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvdevice.c#L1266-L1397)). URL syntax differs between devices: Aravis master's fake camera writes `Local:///name;%x;%x` ([arvfakecamera.c#L1046](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvfakecamera.c#L1046)), while the 0.8.30 fake camera we ran returned `Local:arv-fake-camera.xml;10000;3e67`. pyGigEVision's parser is at [genicam.py#L33-90](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/genicam.py#L33-L90).
* **Stream channel 0** registers: port `0x0D00`, packet size `0x0D04` (bit31 fire test, bit30 do-not-fragment, low 16 bits size), delay `0x0D08`, destination `0x0D18` ([arvgvcpprivate.h#L126-137](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L126-L137); the generic `0x0d00+0x40*i` map is in [W#L148-160](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L148-160)). Aravis's **packet-size negotiation** binary-searches with fire-test packets while do-not-fragment is set ([A/src/arvgvdevice.c#L614-784](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvdevice.c#L614-L784)). The 64-bit block-ID enable is `0x0960` bit `0x40000000` ([W#L3658-3661](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L3658-3661)).
* **PACKETRESEND**: the standard-ID payload is `{u16 channel, u16 block, u32 first(24b), u32 last(24b)}`. The extended-ID form is `{u32 0, u32 first, u32 last, u64 block}` with header flag 0x10 ([A/src/arvgvcp.c#L406-440](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcp.c#L406-L440); [W#L1555-1622](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L1555-1622)).
* **ACTION_CMD**: payload `device_key, group_key, group_mask [, u64 action_time if flag 0x80]` ([W#L2092-2115](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L2092-2115); flag at [#L2517-2518](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L2517-2518)). Capability bits: action `0x40`, scheduled action `0x00020000`, unconditional `0x00100000` ([#L3468-3501](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L3468-3501)). Registers: `0x0908` number of action signals, `0x090C` device key, `0x0970` scheduled queue size ([#L110-133](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L110-133)). Of the three, **only viva-genicam implements action commands** ([crates/viva-gige/src/action.rs#L17-26, L108-211](https://github.com/VitalyVorobyev/viva-genicam/blob/60c9c329a4175290b7065a74027c151cb0acd9ef/crates/viva-gige/src/action.rs#L17-L211)). Telegenic's command table stops at EVENTDATA ([gvcp.rs#L26-46](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/src/gige/proto/gvcp.rs#L26-L46)), and pyGigEVision has none.

### 2.2 GVSP (UDP, camera to host)
* Header: `u16 status, u16 block_id, u32 {EI bit31 | content type bits24-30 | packet_id 24b}`. In extended-ID mode the header is `u16 status, u16 flags, u32 infos, u64 block_id, u32 packet_id` ([A/src/arvgvspprivate.h#L32-36, L132-145, L252-255](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvspprivate.h#L132-L145); EI bit in [W/packet-gvsp.c#L33](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvsp.c#L33)). Content types: 1 leader, 2 trailer, 3 payload, 4 all-in, 7 multipart, 8 GenDC ([arvgvspprivate.h#L109-118](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvspprivate.h#L109-L118)).
* The image leader carries `payload_type`, a **64-bit device timestamp**, pixel format, width, height, offsets and padding ([arvgvspprivate.h#L152-192](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvspprivate.h#L152-L192)). Payload types: image (raw PFNC pixels), raw data, file, chunk, **JPEG (0x6), JPEG2000 (0x7), H.264 (0x8)** (all GEV 2.0), multipart (2.1), GenDC (2.2) ([W/packet-gvsp.c#L43-54](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvsp.c#L43-54); [A/src/arvbuffer.h#L79-92](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvbuffer.h#L79-L92)).
* Overhead per data packet is IP 20 + UDP 8 + GVSP 8, or 20 with extended IDs ([arvgvspprivate.h#L258-275](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvspprivate.h#L258-L275)). Payload per packet is therefore `SCPS - 36` bytes.
* Reassembly, reordering, resend: Aravis `_process_packet` ([arvgvstream.c#L891-992](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvstream.c#L891-L992)) and `_missing_packet_check`, which applies a per-packet timeout and a request-ratio cap and coalesces contiguous gaps into one PACKETRESEND ([#L659-746](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvstream.c#L659-L746); sender at [#L198-222](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvstream.c#L198-L222)). On Linux Aravis can use a `PF_PACKET` + `PACKET_RX_RING` (TPACKET_V3) zero-copy path ([#L1227-1367](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvstream.c#L1227-L1367)). pyGigEVision does it in pure Python with one `recvfrom` per packet in a thread ([gvsp.py#L548-606](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/gvsp.py#L548-L606)), resending from the stream socket ([#L739+](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/gvsp.py#L739)).

### 2.3 PTP: bootstrap registers and GenApi features; no new packets
* PTP is configured and read through registers. The client sends no PTP packets of its own; the camera runs the IEEE 1588 stack. Bootstrap view (Wireshark): capability `0x0934` bit `0x00080000`, enable in `0x0954` bit `0x00080000`, status `0x096C` & 0xF, profiles `0x0974/78/7C` (links in §1). Timestamp tick frequency is at `0x093C/0x0940` and timestamp control/latch at `0x0944` (latch=0x2, reset=0x1, [W#L3566-3575](https://gitlab.com/wireshark/wireshark/-/blob/98a6cfdba1ab23f3c835b17df802004bc9429040/epan/dissectors/packet-gvcp.c#L3566-3575)), with the latched value at `0x0948/0x094C` ([A/src/arvgvcpprivate.h#L116-120](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvcpprivate.h#L116-L120)).
* A real camera XML maps the SFNC features onto exactly those bits. In the Hikrobot XML vendored by telegenic, `GevIEEE1588` is Boolean → `GevIEEE1588PTPEnable_Bit`, which is Bit 12 of the StructReg at **0x0954** ([Hikrobot.xml#L49998](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/tests/data/Hikrobot.xml#L49998), [#L51846-51900](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/tests/data/Hikrobot.xml#L51846-L51900)). GenApi BigEndian bit 12 equals mask `1<<(31-12)=0x00080000`, which matches Wireshark. `GevIEEE1588Status` → MaskedIntReg **0x096C** LSB31/MSB28, i.e. mask 0xF ([#L50338](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/tests/data/Hikrobot.xml#L50338), [#L50490](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/tests/data/Hikrobot.xml#L50490)). `ActionDeviceKey` → IntReg **0x090C**. A minimal client can therefore read PTP state with READREG alone, but it needs GenApi for vendor features and for the BigEndian bit-numbering convention. My first toy MaskedIntReg implementation got that convention wrong; it is fixed in the probe.

## 3. GenApi is the hard part

Measured on real XMLs ([results/genapi_formula_coverage.txt](results/genapi_formula_coverage.txt), produced by `tests/genapi_formula_coverage.py`):

| XML | named nodes | IntSwissKnife+SwissKnife | Converter+IntConverter | selectors (pSelected) | pIsAvailable/Implemented/Locked | pInvalidator | pAddress/pIndex |
|---|---|---|---|---|---|---|---|
| Hikrobot (telegenic test data) | 2165 | 283 | 58 | 41 | 406 | 370 | 513 |
| Imperx (telegenic test data) | 1386 | 402 | 0 | 7 | 193 | 392 | 11 |
| Aravis fake camera | 62 | 1 | 2 | 0 | 0 | 0 | 3 |

* A toy SwissKnife translator (Python `ast` whitelist) parses 372/399 (Hikrobot) and 389/402 (Imperx) formulas. The failures are nested `?:`. Parsing is the easy 90%. Selectors, availability/lock predicates, cache invalidation and computed addresses are the real work, and the fake camera exercises none of them.
* Size of existing GenApi implementations: Aravis `arvgc*.c` + evaluator + DOM/XML ≈ 14.7k lines of C (`arvevaluator.c` alone is 1521). cameleon-genapi ≈ 11.8k lines of Rust. viva-genapi + viva-genapi-xml ≈ 21.5k lines of Rust. Telegenic's `src/genicam/` ≈ 3.3k lines of Rust (evaluator 580, node 1288, xml 524). pyGigEVision has **no evaluator**: its README tells users to configure "vendor-specific registers (Width, Height, PixelFormat, ...) via client.write_reg()" ([README.rst#L30-47](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/README.rst#L30-L47)). Its `genicam.py` only downloads the XML.
* Reusable GenApi engines:
  * **Python**: the official EMVA `genicam` wheel (C++ reference GenApi v3.5, bundled `libGenApi_gcc8_v3_5.so`). You subclass `genapi.AbstractPort` with `read(address,length)`/`write(address,value)`, as harvesters does ([port.py#L31-67](https://github.com/genicam/harvesters/blob/383494e36ebb80e2daa271ac0e980dde2093970c/src/harvesters/_private/core/port.py#L31-L67)). **Tested here**: my pure-Python GVCP port drives it against the Aravis fake camera. Caveats seen: on Linux the wheel links `libpython3.12.so.1.0` (ImportError in a default ubuntu venv until `libpython3.12t64` was installed), and there is no macOS x86_64 wheel. `NodeMap.__setattr__` maps attributes to features, so the port object cannot be stashed on the NodeMap.
  * **Rust**: `cameleon-genapi` (transport-agnostic `Device` trait with `read_mem`/`write_mem`, [genapi/src/lib.rs#L82-95](https://github.com/cameleon-rs/cameleon/blob/1ab3fbf82a11f94da56e35a62893a6042054df4b/genapi/src/lib.rs#L82-L95); cameleon itself is U3V-only and lists GigE on its roadmap, [README.md#L28](https://github.com/cameleon-rs/cameleon/blob/1ab3fbf82a11f94da56e35a62893a6042054df4b/README.md#L28), [#L166-170](https://github.com/cameleon-rs/cameleon/blob/1ab3fbf82a11f94da56e35a62893a6042054df4b/README.md#L166-L170)), `viva-genapi`, and telegenic's built-in evaluator ([README.md#L40-64](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/README.md#L40-L64)).
  * **C++**: the same EMVA reference GenApi, or Aravis (C/GLib, LGPL).

## 5. OS receive-buffer limits and Windows drivers
* Linux: `SO_RCVBUF` is doubled and capped by `net.core.rmem_max`. `SO_RCVBUFFORCE` (CAP_NET_ADMIN) bypasses the cap ([socket(7), man-pages 6.19, 2026-06-05](https://man7.org/linux/man-pages/man7/socket.7.html)). Measured: a 16 MiB request became 425,984 (capped) or 33,554,432 (forced). An app should tell users to set `sysctl -w net.core.rmem_max=...`, as Aravis and vendors do. Aravis sets buffer = frame size + 1024 in AUTO mode ([arvgvstream.c#L225-265](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvgvstream.c#L225-L265)) and verifies with getsockopt ([arvnetwork.c#L461-514](https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/src/arvnetwork.c#L461-L514)). Telegenic defaults to 8 MiB and reports `socket_drops` from the kernel ([README.md#L66-120](https://github.com/valstad-shipworks/telegenic/blob/eb9de6579dde096b4a60ccead934edcc3795d6c3/README.md#L66-L120)). pyGigEVision requests 16 MiB and silently ignores failure ([gvsp.py#L347-350](https://github.com/ladisk/pyGigEVision/blob/2de253135b8766c1eb752226539a16b810a1cf0f/pyGigEVision/gvsp.py#L347-L350)).
* macOS: `kern.ipc.maxsockbuf` → `sb_max = SB_MAX = 8192*1024` ([xnu socketvar.h#L193](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/socketvar.h#L193), [uipc_socket2.c#L143, L806-825, L2956-2976](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/uipc_socket2.c#L2956-L2976)). Not measured here; no Mac available.
* Windows: default `SO_RCVBUF` measured at 65,536, and a 16 MiB request was granted. Vendors ship NDIS **filter drivers** to cut CPU load. Basler's docs say: "The pylon GigE Vision Filter Driver ... Optimizes and lowers the CPU load ... available for Windows only". The Performance Driver was deprecated in pylon 7.1, and the "Socket Driver ... uses the Socket API" ([docs.baslerweb.com/pylon-software-suite](https://docs.baslerweb.com/pylon-software-suite)). A from-scratch client always gets the socket-driver path.

## 6. Options, effort, risks

Effort is in person-weeks for one experienced developer and covers the SkellyCam need: discovery/ForceIP, control, GenApi, GVSP with resend, PTP enable/status, scheduled actions or `AcquisitionStart`, and Win/macOS/Linux wheels.

| Option | Effort | Basis | Main risks |
|---|---|---|---|
| (a) Pure Python, own GVCP/GVSP + **EMVA `genicam` wheel** for GenApi | **6–9 pw** | The probe here did GVCP + XML + toy GenApi + GVSP + resend in about 830 lines. pyGigEVision ≈ 2.0k lines without GenApi. | GIL (§4.3): one process per camera, or 3.14t. rmem_max/firewall setup. No filter driver. The wheel needs libpython.so, has no mac x86_64 build, and is under the GenICam license. 10 GbE at MTU1500 (813k pps) is beyond one Python core. |
| (a′) Pure Python incl. own GenApi | 12–18 pw | GenApi engines run 3–22k lines (§3) | Vendor XML edge cases: selectors, invalidators, BigEndian bit numbering (a trap seen here), nested formulas |
| (b) Rust + PyO3 from scratch | 10–16 pw (−4 to 6 with `cameleon-genapi`) | Telegenic reached 2.1.0 (9.3k lines with PyO3) in about 4 months; viva-genicam reached 0.10.0 in about 6 months | Rust skills in team. Wheel CI for 3 OSes (maturin). |
| (b′) **Adopt or extend telegenic or viva-genicam** (already Rust + PyO3 on PyPI) | 1–3 pw integration (+1–2 pw to add ACTION_CMD to telegenic) | §0 and §2.1 | Young projects (first publish 2026-04/06), single maintainers, pre-1.0 API churn (viva) |
| (c) C++ + nanobind/pybind11 from scratch + EMVA GenApi | 9–14 pw | GVCP/GVSP 4–6 pw, GenApi embedding 2–3 pw, bindings + cibuildwheel 2–3 pw | Native build matrix, GenICam reference library licensing and redistribution |

Risks common to all options:
* Real-camera interop: discovery-ACK variants, pending ACKs, CCP/heartbeat semantics during debugging, packet-size negotiation where fire-test is missing.
* Resend tuning.
* PTP happens camera-side; you still need a grandmaster (a camera or a switch/host running PTP) and must read `GevIEEE1588Status` until it shows Master/Slave.
* GEV 3.0 RDMA (GVRSP) is out of reach without a native verbs library.
