## Verdicts

| C1 | supported (with nuance) | PTP, scheduled action, ACTION_LATE and the 1588 status register are all tagged `_v2_0` / `/* GEV 2.0 */`. The profile registers 0x974-0x97C (PTP-profile and 802.1AS-profile bits) are tagged `_v2_1`. **Nuance:** *plain* action commands are older than 2.0. Wireshark's `hf_gvcp_capability_action_command` (0x40) and the unconditional-action capability have no version suffix, while v1_1 and v2_0 fields do. The quote in issue #184 ("GigEVision 2.0 introduces Action Commands") is therefore imprecise: 2.0 introduced *scheduled* action commands. |

## Missed points (sources opened)
1. **GigE Vision 3.0 exists.** A3 released it on 2026-05-12. It adds RDMA over RoCEv2 (GVRSP) and a larger control channel. The press release says nothing about PTP or timing, so it reinforces "PTP is 2.x, not 3.0". https://www.vision-systems.com/directory/software/machine-vision-imaging-software/press-release/55377111/association-for-advancing-automation-a3-a3-officially-releases-gige-vision-30-opening-new-possibilities-in-machine-vision
2. **GEV 2.1 adds IEEE1588 profile selection, including an 802.1AS (gPTP) profile bit 0x40000000** (PTP profile 0x80000000) at 0x974/0x978/0x97C. https://gitlab.com/wireshark/wireshark/-/blob/02dbbdbf41aecc1f2a4ba6c0db2546af5bb07d75/epan/dissectors/packet-gvcp.c#L3388-3398
3. **The Windows inbox PTP client won't sync to a GM unless PTP_TIMESCALE and PTP_UTC_REASONABLE are set.** A free-running camera grandmaster probably fails this, so slaving the Windows host to the cameras via w32time is not a reliable path. Validation Guide .docx: https://github.com/microsoft/W32Time/blob/9795ef91dfe5a452266ffd8106ff2bcb17f33556/Precision%20Time%20Protocol/docs/Validation%20Guide%20-%20Precision%20Time%20Protocol.docx
4. **Aravis HEAD (2026-10-03, ee31d82, after 0.9.2) adds `aravissrc add-reference-timestamp-meta`.** It attaches the device timestamp as GstReferenceTimestampMeta with `timestamp/x-ptp` caps ("Only an absolute time if the device clock is PTP-synchronized"). https://github.com/AravisProject/aravis/blob/482547a3d56e3aa8d22d7ffed33c9f1588bfe17a/gst/gstaravis.c#L563-L567 and #L1203-L1208
5. **LUCID's scheduled-action app note (?p=4184) is the actual source of the "7 cameras" output.** It uses PtpEnable / PtpSlaveOnly / PtpStatus, then PtpDataSetLatch + PtpDataSetLatchValue (not TimestampLatch), then ActionCommandFireCommand. The sample timestamps run from 2074000024760 to 2074000033912 ns against a scheduled time of 2074000000000: a spread of about 9.15 µs, all frames 25-34 µs late. https://support.thinklucid.com/?p=4184
6. **Aravis issue #184 was opened by "thecaptury"** (The Captury, a markerless-mocap vendor). The only maintainer comment (EmmanuelP, 2019-08-15) asks whether a contributor's work is usable, and there is no reply. https://github.com/AravisProject/aravis/issues/184
7. **Allied Vision firmware below 01.54.11026 used a different PtpStatus set** [Off, Master, Syncing, Slave, Error]. Newer firmware is 0-based Initializing(0)..Slave(8), Invalid(9), whereas SFNC uses 1..9. Read enums by name. (AV PDF pp.4, 9.)
8. **Basler: BslPtpPriority1 is adjustable only on ace 2/dart M** (fixed at 128 elsewhere). For external masters Basler recommends an ANNOUNCE interval of 2 s and SYNC of 0.5 s, and P2P delay needs all switches PTP-enabled. https://docs.baslerweb.com/precision-time-protocol
9. **GenTL SFNC Interface action features are only "Recommended"**, so producers may omit them. https://www.emva.org/wp-content/uploads/GenICam_GenTL_SFNC_1_2.pdf (§3.2.3)
