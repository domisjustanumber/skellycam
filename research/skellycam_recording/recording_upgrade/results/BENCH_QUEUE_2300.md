## What the runner does

| step | behaviour | evidence |
|---|---|---|
| start (read-only) | records the power plan, display/sleep idle timeouts, Defender schedule, display adapters, P-core set, free disk and nvidia-smi | code: `run_queue.py` `start_state()` |
| iGPU check | checks once for `Intel(R) UHD Graphics 770` with Present True. If it is absent: items tagged `qsv` are skipped, and `qsv_optional` items get `--skip-qsv`. Both are logged | code: `igpu_present()`, item loop |
| display | calls `SetThreadExecutionState(ES_CONTINUOUS\|ES_SYSTEM_REQUIRED\|ES_DISPLAY_REQUIRED)` for the runner's lifetime. This is a per-process request; no power setting is changed. Reason: the display turns off after 600 s on AC (measured: `powercfg /q` VIDEOIDLE AC index 0x258, read 2026-11-09), and the Electron benches need a visible window | code: `main()` |
| before each item | records 10 s typeperf total CPU, the top 10 processes by CPU seconds in the same window, nvidia-smi (encoder sessions and utilisation), and free disk. If the mean CPU is above 15 %, it re-checks every 30-40 s for up to 5 min, then runs the item anyway with the flag `load_over_15pct` | code: `load_record()` |
| timeout | hard per-item timeout. On expiry it kills the whole process tree (psutil, then `taskkill /T /F`) | code: `kill_tree()` |
| deadline | starts no item after 05:00, and no item whose estimate would end after 05:00. Skipped items are logged | code: item loop |
| Defender | waits out the avoid window 01:55-02:30 (configured daily quick scan at 02:00). It also logs Defender scan events (Operational log ids 1000/1001) and MsMpEng CPU seconds per item | code: `windows()`, `defender_scans_since()`, `msmpeng_cpu_s()` |
| affinity | runs each item on the P-cores. Detected via `GetLogicalProcessorInformationEx`: 8 cores of EfficiencyClass 1 out of 20 cores, classes [0, 1]. The runner sets its own affinity before creating the child; the children inherit it | measured: smoke snapshots record `process_cpu_affinity` = [0..15] inside the bench processes |
| smoke | runs each item's `smoke_command`, without the load wait. Folders listed in an item's `watch` are snapshotted, then new files are deleted and changed files restored, so no smoke output stays in `results/<topic>/bench/` | code: `snap()`, `backup()`, `restore()` |

## Defender and scheduling (read-only, 2026-11-09 18:54)

- **measured: configured schedule.** `Get-MpPreference` returns ScanScheduleDay 0, ScanScheduleTime 02:00:00, ScanScheduleQuickScanTime 00:00:00, ScanScheduleOffset 120, ScanParameters 1, ScanOnlyIfIdleEnabled True, SignatureScheduleDay 8.
- **source: what those values mean.** https://learn.microsoft.com/en-us/powershell/module/defender/set-mppreference (accessed 2026-11-09):
  - ScanScheduleDay: "0: Everyday", "8: Never".
  - ScanParameters: "1: Quick scan".
  - ScanScheduleQuickScanTime: "If you do not specify a value for this parameter, a scheduled quick scan runs at the time specified by the **ScanScheduleOffset** parameter. That parameter has a default time of two hours after midnight."
  - ScanOnlyIfIdleEnabled: "start scheduled scans only when the computer is not in use".
- **NOT VERIFIED: the midnight reading.** Whether `ScanScheduleQuickScanTime 00:00:00` means "not set" or "midnight" is not established.
- **measured: when scans actually ran.** The Defender Operational log shows the quick scans of 2026-11-04 to 11-09 starting in the daytime (10:50, 11:44, 15:27, 13:14, 12:03, among others), each finishing about 2.5-4.5 min later. None started at 00:00 or 02:00.
- **Mitigation.** The queue reserves 01:55-02:30 as a gap. A scan at any other time shows up as the `load_over_15pct` flag, MsMpEng CPU, or a scan event in that item's log line.
- **Planned schedule** (dry run `--dry-run --dry-start 23:00`, 2026-11-09; estimates plus the runner's 25 s overhead per item):
  - items 1-21 end at about 01:53;
  - the runner then waits until 02:30 (the Defender gap);
  - items 22-23 end at about 02:35;
  - the appended items 24-43 run from 02:35 to about 04:59 (item 43 starts 04:54);
  - **items 44-68 are skipped by the 05:00 deadline at these estimates** (172.6 min of estimates). The runner skips an item whose estimate would end after 05:00 but still starts any later item that fits, so if items finish early, more of the tail runs, in order.
  - Planned item time before 05:00: 305.2 min of the 477.8 min listed.
  - Without the deadline the whole queue would end at about 08:03 (dry run with `--deadline 10:00`). To get it, resume in the next quiet window with `--start-from <first skipped id> --deadline HH:MM` (a daytime start needs an explicit deadline: the default 05:00 would already have passed).

## Notes for reading tonight's results

- **The input work is in the timed loop** (`benchpaths.py` docstring).
  - The range change for NV12/YUY2 sources is done untimed.
  - For MJPEG sources the decode and the swscale range change are timed. For a 4:2:0 path fed YUY2 (`IC-SCALE-h264_nvenc_420-yuy2`) the swscale yuyv422 -> NV12 step is timed.
- **nvJPEG from host NV12/YUY2/MJPEG goes through swscale RGB.** intra_compare NOTES §9.3 measured that swscale RGB costs PSNR-Y. Read each row's `quality_check` before comparing. The `rgb` source isolates the encode call at the matched setting.
- **The quality check is per row** (single-stream items): PSNR-Y / SSIM-Y of the first 4 frames of that exact pipeline.
- **GPU Engine counters are per process**, sampled from the bench process's own `\GPU Engine(pid_<pid>_*)` instances. Read Intel engine names as reported.
- **Electron windows must be visible.** Leave the session unlocked; the runner keeps the display on.
- **P-cores only.** Results are for 16 logical CPUs, not all 28. Label them so.
- **CR-FSYNC confounder** (crash_resilience FINDINGS §5): its `mkv_fp_fsync_K` policy writes through a Python file object.
- **New scaling items use 2 reps**, the decisive items 4-11 use 3.
- **Outside the hardware target:** UI-BAYER-AV19 and UI-CORE-AV19 (FFV1 / rawvideo) are there for G4 only, as the CPU fallback; say so wherever they are quoted.
- **PI-JPEG-DECODE-PYAV19 uses libjpeg-turbo 3.2.1**, not the 3.2.0 named in the script docstring (no download at run time). The DLL path is in the JSON `env.turbojpeg_dll`.
- **PI-NVJPEG-DECODE uses nvImageCodec 0.9.0.20** (script pin), while the intra_compare benches use 0.10.0.9. Its old note about a long `UV_CACHE_DIR` did not apply: the smoke passed with the default uv cache.
- **CR-REPAIR-PYAV19 counts frames with ffprobe** (inspection, after the timed call). The ffmpeg `-c copy` repair rows are not run.
- **The write cells regenerate `results/write_throughput/bench/bench_summary.md`** over every set folder (code: `run_matrix.py` -> `summarize_bench.py`). Separate PyAV 18 and 19 rows by `env.av`.
- **Smoke "leftover processes" flags:** the flag on the smoke of item 31 (and any other smoke item) listed only this session's own monitoring shells (their command lines contained the scratchpad path); no bench process was left behind.
